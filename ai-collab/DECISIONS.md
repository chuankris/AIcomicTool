# 协作决策记录

这个文件记录已经达成的产品、技术和协作决策。后续 AI 接手时，优先沿用这些决策，除非用户明确要求改变。

## 产品决策

### 2026-04-22：项目定位

本项目定位为“AI 漫剧/漫画分镜生产工具”，不是展示型网站，也不是单纯 prompt demo。所有 UI 和功能优先服务真实创作流程：输入、生成、审核、修改、重生成、导出。

### 2026-04-22：主流程采用项目工作台

首页是项目列表和新建项目入口。项目创建后进入项目详情页，不再使用早期独立 `/create` 向导。

### 2026-04-22：项目详情采用 Stepper 流程

当前项目详情页采用三步：

1. 剧本 & 角色
2. 分镜 & 出图
3. 配音 & 导出

早期文档中提到的四 Tab 方案属于历史方案，除非用户要求，不要回退。

### 2026-04-22：用户自带 Key

系统不提供统一账号或平台级 Key。用户在本地设置页保存自己的文本模型 Key 和即梦凭证。

### 2026-04-22：提示词交互采用 Tip + 局部反馈

生成前优先使用动态 Tip/选项收集用户意图，例如剧本节奏、改写幅度、分镜密度、镜头风格。生成后再提供聊天式自然语言反馈，用于局部修正角色、分镜、prompt 或风格。不要把主流程改成纯聊天产品。

### 2026-04-22：风格系统需要升级为组合式视觉词库

现有“日漫/韩漫/美漫/国风”过粗。后续风格应拆成“基础画风 + 视觉题材 + 画面气质”，例如“日漫 + 机甲科幻 + 冷色电影感”或“厚涂漫画 + 末日废土 + 压迫感”。风格词库应服务图像模型 prompt，而不仅是给用户看的分类。

### 2026-04-22：Step 2 出图采用两段式确认

Step 2 不是进入页面就自动出图，而是先生成/编辑分镜脚本，再由用户点击“开始出图”调用即梦批量生成图片。进入 Step 2 的默认状态是 `editing_shots`，允许调整分镜策略、视觉风格和分镜内容；点击“开始出图”后进入 `generating_images`，生成中锁定分镜策略和全局视觉风格，避免状态混乱和浪费额度。

### 2026-04-22：Step 2 支持单格试生成

在批量“开始出图”前，每个分镜卡片都可以单独点击“生成此格”，用于先验证视觉风格、角色一致性和 prompt 效果。单格生成不应强制锁定整个 Step 2；用户仍可继续调整未生成分镜和全局设置，但已生成图片不会被全局设置自动覆盖。

### 2026-04-22：出图能力先做加法，UI 渐进暴露

底层能力应先考虑完整的导演控制项：画幅/分辨率、清晰度、角色参考图强度、背景参考图强度、字幕安全区、负面词、seed、单格高级设置等。但默认 UI 保持简单，高级参数折叠，后续根据真实使用再做减法。

### 2026-04-22：分镜出图必须利用角色/背景参考图

分镜图片应引用 Step 1 生成的角色参考图，以提高角色一致性；背景场景也应支持参考图和强度控制。最终即梦 prompt 应合成“全局视觉风格 + 当前分镜 + 角色锁定词/参考图 + 背景参考 + 单格反馈 + 画幅/安全区约束”。

### 2026-04-22：Step 1 是创作前期设定台

Step 1 不只是剧本输入页，而是进入分镜前的设定台。它应产出：整理后的剧本、已确认角色、已确认背景场景、角色锁定词、角色参考图、背景场景参考图，以及剧本级节奏/润色偏好。

### 2026-04-22：AI 提取结果先进入建议区

AI 从剧本提取出的角色和背景不应直接污染正式项目设定，应先进入“AI 提取建议”区域。用户逐个确认后，才加入已确认角色或已确认背景场景。

### 2026-04-22：专业导演层能力先入文档，暂缓实现

情绪曲线、信息揭示节奏、表演指导、SFX/环境声、成片时长预估、审核合规边界、标题/封面钩子、机位/站位连续性、系列化、BGM、素材资产库、旁白/屏幕文字等能力都很重要，但先作为高规格需求进入 `docs/director-foundation-checklist.md`。当前阶段不急于全部实现，先打好 Step 1/Step 2 主流程地基，使用一段时间后再做取舍。

## 技术决策

### 2026-04-22：本地 SQLite 持久化

当前使用 SQLite + Drizzle ORM，本地保存项目、角色、分镜、设置和即梦凭证。短期内不要引入远程数据库或登录系统，除非用户明确要求多人/云端能力。

### 2026-04-22：文本模型走 OpenAI SDK 兼容层

`src/lib/ai/model-client.ts` 统一封装 Claude / OpenAI / Gemini / 自定义 OpenAI-compatible endpoint。新增文本 AI 能力时优先复用 `callModel`。

### 2026-04-22：图片生成当前只实际支持即梦

类型中存在 `mj-niji`、`sd-xl`、`kling` 等未来扩展，但实际生成客户端目前是即梦。不要在 UI 中承诺尚未接入的图片模型能力。

### 2026-04-22：生成任务目前是 API route 内异步继续执行

`POST /api/projects/[token]/generate` 返回 202 后继续在服务端异步生成。这个方式适合本地开发，但如果部署到 serverless 环境，需要重新设计任务队列或 worker。

### 2026-04-22：Plan B 是 TTS + FFmpeg 导出

导出阶段目标是：每格分镜按台词生成音频，再用 FFmpeg 合成 720x1280 竖屏 MP4。当前还未实现。

### 2026-04-22：角色与背景 prompt 必须分开

角色参考图和背景场景图是不同任务。背景场景不能复用角色 prompt 模板，避免生成“正面全身”“角色参考图”等错误关键词。

## 协作决策

### 2026-04-22：Codex 和 Claude Code 共享文件化上下文

两边交接时不依赖聊天记录。每次重要修改后更新 `ai-collab/HANDOFF.md`，需要时同步 `ai-collab/TASKS.md` 和 `ai-collab/DECISIONS.md`。

### 2026-04-22：单任务单 owner

一次任务尽量只让一个 AI 负责同一块代码。尤其避免两个 AI 同时修改：

- `src/app/project/[token]/page.tsx`
- `src/components/project/*`
- `src/lib/db/schema.ts`
- `src/types/index.ts`
- `src/app/api/projects/[token]/generate/route.ts`

### 2026-04-22：完成任务必须留下验证状态

每次交付至少说明：

- 修改了哪些文件
- 为什么这样改
- 跑了哪些检查
- 没跑哪些检查以及原因
- 下一个接手者需要注意什么
