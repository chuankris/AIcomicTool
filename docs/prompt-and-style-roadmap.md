# 提示词与风格系统路线图

最后更新：2026-04-22

## 背景

当前 AI 漫剧生成链路已经可以跑通：剧本润色、角色/背景提取、分镜拆解、分镜出图。但 demo 暴露出几个问题：

- 剧本润色偏通用“文学化增强”，缺少用户可控的节奏和改写幅度。
- 角色和背景场景共用了角色属性拆解与角色参考图 prompt 逻辑，导致背景 prompt 出现“正面全身，角色参考图”等不合适词。
- 分镜拆解能输出结构，但缺少分镜密度、镜头风格、空镜策略等用户意图控制。
- 漫画风格只有“日漫/韩漫/美漫/国风”等大类，不足以指导即梦生成机甲、末日废土、赛博朋克、性感魅惑等更具体视觉风格。

本路线图先记录方案，不代表已经开始改代码。

## 交互策略

采用“前置动态 Tip + 可选补充要求 + 后置聊天式局部反馈”的混合模式。

### 前置动态 Tip

适合在生成前收集用户意图，避免用户每一步都写长 prompt。

剧本润色前：

- 节奏：短剧冲突 / 漫画分镜 / 文学氛围 / 保守整理
- 改动幅度：轻度 / 中度 / 大胆改写
- 台词风格：自然口语 / 青春感 / 古风 / 克制含蓄

角色/背景提取前：

- 提取范围：主要角色 / 主要+配角 / 角色+背景场景
- 设定细节：简洁 / 详细
- 外貌补全：只按原文 / 允许合理补全

分镜拆解前：

- 分镜密度：关键镜头 / 标准 / 细分动作
- 镜头风格：漫画格子 / 电影感 / 短视频强冲突
- 空镜/转场：不加 / 适量加入

### 可选补充要求

每个生成区保留一条自然语言输入，例如：

- “多给小龙女特写，少用远景”
- “保持暧昧感，不要把告白说破”
- “整体更赛博朋克，雨夜霓虹更强”

### 后置聊天式局部反馈

结果出来后，用户可以对局部结果用自然语言反馈，AI 基于当前结构化结果修改，而不是从零生成。

适合场景：

- 修改某个角色设定
- 合并/拆分某些分镜
- 调整某格 prompt
- 强化某种风格或氛围
- 删除 AI 误补的角色/场景

## 提示词工程方向

### 创作型任务

包括：

- 剧本润色
- 分镜场景增强
- 即梦 prompt 润色

特点：

- 可以有一定创造性。
- 需要用户控制风格、幅度、节奏。
- 可以使用较高 temperature，但仍应保持任务边界。

建议：

- 使用动态 Tip 作为 prompt 变量。
- 明确“保留原剧情”或“允许改写”的边界。
- 给 2-3 个产品内 few-shot 示例。

### 抽取型任务

包括：

- 角色/背景提取
- 角色属性拆解
- 分镜 JSON 拆解

特点：

- 输出需要落库。
- 稳定性比创造性更重要。
- 不适合完全自由聊天。

建议：

- 低 temperature。
- 明确 JSON schema。
- 支持 structured output 的 provider 优先走 schema。
- 不支持 schema 时走“强提示词 + JSON parse + repair retry”。
- 失败时返回可编辑草稿，不要静默失败或落脏数据。

## 风格系统方向

当前单个 `style` 字符串太粗，应升级为“基础画风 + 视觉题材 + 画面气质”的组合。

### 基础画风

决定线条、上色和漫画类型：

- 日漫
- 韩漫
- 美漫
- 国风
- 厚涂漫画
- 黑白漫画
- 复古漫画
- 儿童绘本
- 写实漫画
- Q版漫画

### 视觉题材

决定世界观、服装、材质、场景和道具：

- 机甲科幻
- 末日废土
- 赛博朋克
- 暗黑哥特
- 都市夜景
- 校园青春
- 奇幻魔法
- 武侠江湖
- 古风仙侠
- 悬疑惊悚
- 蒸汽朋克
- 太空歌剧
- 霓虹街头
- 末世校园
- 怪谈民俗
- 性感魅惑
- 高级时装
- 战斗热血
- 治愈日常
- 港风复古

### 画面气质

决定情绪、色调和镜头观感：

- 明亮
- 阴郁
- 热血
- 浪漫
- 压迫感
- 电影感
- 高级感
- 冷色调
- 暖色调
- 高对比
- 柔和光

### 性感/成熟风格边界

可以支持“性感魅惑”“高级时装”“成熟都市”等方向，但 prompt 应强调成熟气质、修身服装、时尚姿态、精致妆容、魅惑氛围、高级感、非露骨，避免露骨色情表达。

## 风格词库建议

先建立一个可被 UI 和 prompt-builder 共用的风格词库，再改 UI。

示例结构：

```ts
interface StylePreset {
  id: string
  label: string
  group: 'base' | 'genre' | 'mood'
  prompt: string
  negative?: string
}
```

示例：

```ts
{
  id: 'mecha_scifi',
  label: '机甲科幻',
  group: 'genre',
  prompt: '机甲科幻世界观，巨型机械装甲，金属结构，冷色调灯光，工业细节，高科技界面'
}
```

```ts
{
  id: 'wasteland',
  label: '末日废土',
  group: 'genre',
  prompt: '末日废土世界观，破败城市，沙尘天空，废弃车辆，锈蚀金属，荒凉压迫感'
}
```

```ts
{
  id: 'cyberpunk',
  label: '赛博朋克',
  group: 'genre',
  prompt: '赛博朋克都市，霓虹灯牌，雨夜街道，高楼阴影，义体科技，紫蓝粉高对比光影'
}
```

```ts
{
  id: 'seductive_fashion',
  label: '性感魅惑',
  group: 'genre',
  prompt: '成熟气质，修身时装，精致妆容，魅惑氛围，高级时尚感，非露骨表达'
}
```

## 建议实施顺序

1. 建立提示词 demo/eval 脚本：固定输入，比较当前提示词和新版提示词。
2. 拆分角色 prompt 和背景 prompt。
3. 为剧本润色、角色提取、分镜拆解增加 Tip 参数设计。
4. 建立风格词库，不急着改 DB。
5. UI 上先使用标签组合生成复合 `style` 文本，后续再升级数据结构。
6. 引入 JSON schema 或 repair retry，提升结构化输出稳定性。

## 验收标准

- 同一测试剧本下，角色提取不重复、不漏主要角色。
- 背景场景 prompt 不再出现“正面全身/角色参考图”等角色词。
- 分镜数量和密度受用户选择影响。
- 风格组合能明显影响最终 prompt。
- 结构化输出失败时有可理解错误或自动修复，不直接 500。
